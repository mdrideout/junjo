# Protocol Buffer Tool Versions

This document specifies the locked Protocol Buffer compiler used to build
Studio's two Rust services.

> **Note:** No generated proto code is checked in. The backend and ingestion
> each compile the files in [`proto/`](proto/README.md) at build time with
> `tonic-prost-build`, which uses the system `protoc` binary.

## Required Tool Version

| Tool | Version | Purpose |
|------|---------|---------|
| **System protoc** | v30.2 | Build-time compiler for the backend and ingestion |

## Build-time Generation

Generated Rust code is:
- Produced at compile time by `backend/server/build.rs` and
  `ingestion/build.rs`
- Placed in each service's `target/` directory (gitignored)
- Regenerated by `cargo build`, `cargo check`, `cargo test`, and `cargo run`
  when a proto file changes

The system compiler is locked to v30.2 so local, CI, and image builds use the
same input compiler even though the output is not committed.

## Where the Version Is Pinned

- `backend/Dockerfile` and `ingestion/Dockerfile`: the build and development
  stages download the v30.2 release archive, verify its pinned SHA-256
  checksum, and require the exact `libprotoc 30.2` version.
- `../../.github/workflows/studio-backend-tests.yml` and
  `../../.github/workflows/studio-rest-api-contract-validation.yml`: every job
  that compiles a service's build script does the same before compiling.
- `../../tooling/tests/test_ci_release_tools.py` asserts those workflow
  installs.
- `run-all-tests.sh` warns when the local `protoc` is another version.

## Installation Instructions

### macOS

```bash
PROTOC_VERSION=30.2
curl -LO https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/protoc-${PROTOC_VERSION}-osx-x86_64.zip
sudo unzip -o protoc-${PROTOC_VERSION}-osx-x86_64.zip -d /usr/local bin/protoc
sudo unzip -o protoc-${PROTOC_VERSION}-osx-x86_64.zip -d /usr/local 'include/*'
rm protoc-${PROTOC_VERSION}-osx-x86_64.zip
```

### Linux

```bash
PROTOC_VERSION=30.2
curl -LO https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/protoc-${PROTOC_VERSION}-linux-x86_64.zip
sudo unzip -o protoc-${PROTOC_VERSION}-linux-x86_64.zip -d /usr/local bin/protoc
sudo unzip -o protoc-${PROTOC_VERSION}-linux-x86_64.zip -d /usr/local 'include/*'
rm protoc-${PROTOC_VERSION}-linux-x86_64.zip
```

### Windows

```powershell
$PROTOC_VERSION = "30.2"
Invoke-WebRequest -Uri "https://github.com/protocolbuffers/protobuf/releases/download/v$PROTOC_VERSION/protoc-$PROTOC_VERSION-win64.zip" -OutFile "protoc.zip"
Expand-Archive -Path protoc.zip -DestinationPath "C:\protoc" -Force
# Add C:\protoc\bin to your PATH
Remove-Item protoc.zip
```

## Verification

After installation, verify the version:

```bash
protoc --version
# Expected: libprotoc 30.2
```

## Troubleshooting

### "protoc: command not found"
- Ensure protoc is in your PATH
- Verify installation with `which protoc`

### Rust build fails with proto errors
- Ensure `proto/` exists at the Studio root (`apps/studio`)
- Check that `backend/server/build.rs` and `ingestion/build.rs` reference the
  correct paths
- Confirm `protoc --version` reports `libprotoc 30.2`
- Run `cargo clean && cargo build` in the failing service to regenerate

## Version Update Process

When updating protoc version:

1. Update version numbers in this file
2. Update the version and checksums in `backend/Dockerfile`,
   `ingestion/Dockerfile`, `../../.github/workflows/studio-backend-tests.yml`,
   and `../../.github/workflows/studio-rest-api-contract-validation.yml`
3. Update the version `run-all-tests.sh` expects, and the version and checksum
   `../../tooling/tests/test_ci_release_tools.py` asserts
4. Test that `cargo build` still works in `backend/` and `ingestion/`
5. Commit all updated files in a single commit
6. Notify developers to update their local installations
